# キッチン優先の配置

2026-09-29 ローカル修正。本番反映・既存シフトの再生成は未実施。

- 必要人数の配置はポジション名「キッチン」を先に処理する。IDの大小には依存しない。
- 候補者の勤務継続・勤務目標・公平性などが同条件なら、担当可能なポジションが少ない人を優先する。
- 最低勤務時間の延長後、余剰ポジションから不足ポジションへの担当変更を行う。
- 日付・開始終了時刻・出勤人数は変更しない。元ポジションの必要人数を下回る移動や、担当レベルが下がる移動は行わない。経験レベル合計を使う既存ルールを悪化させないため。
- 最終調整は余剰から不足への直接の担当変更に限定。人数不足、担当者不足、複数人の連鎖的な入れ替えが必要なケースは解決を保証しない。
- 最終調整の更新は一括トランザクション。失敗時は担当変更をロールバックする（それ以前の生成全体のロールバックではない）。

検証: JDK 21の `javac --release 17`、RegressionTests 28項目、GenerationTests 29項目、ShiftDisplayTests 9項目、PositionAllocationTests 10項目、計76項目通過。架空データのみ使用。実MySQLでの新SQLの実行・本番データでの生成は未検証。
